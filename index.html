官網設計協作與 UI 交付規範

從客戶需求、後台配置到 Figma 轉碼，說明設計需確認的畫面、內容與互動規則，以及交付 HTML／CSS 時的共同做法。

合作方式

先用現有後台能力組成網站；不足時提出新的品牌樣式或模塊呈現。設計完成 Figma 並可用 AI 輔助轉成 HTML／CSS，開發接手後再處理平台程式架構、資料與功能整合。

適用：每案新增或調整的設計製作數量依需求確認未定規則明確標記，不自行推定
01 / 需求與素材準備

開始設計前，先確認網站要呈現什麼

先整理網站用途、頁面與內容，再評估既有品牌樣式、模塊與頁型是否足夠。沒有固定的風格套數、模塊數或每種三版要求。

準備項目需要確認的內容
網站目的與對象主要訪客、需要傳達的訊息，以及希望訪客採取的行動，例如閱讀、詢問、預約或購買。
網站結構首頁、必要內頁、列表、詳情頁、主選單與頁尾入口；列出每個頁面的用途。
品牌與素材Logo、品牌配色、文字、圖片、圖示、影片與授權來源；缺少的素材標記待補。
內容與資料哪些內容手動填寫、哪些引用後台；有哪些必填欄位、資料量與連結。
操作與限制是否需要選單、分類、展開、輪播或表單；依平台可用能力先確認。
本次製作範圍逐項列出直接沿用、重新設計、需要擴充的部分，以及交付與確認時間。
先提供可參考的起點：現有後台畫面、可用模塊／頁型清單、對應欄位與一組內容樣本。有可用的前台預覽或 HTML，也一併提供，方便設計辨認內容結構。
02 / 後台架構與配置

先定整站風格，再安排頁面與內容

品牌樣式建立全站基準；首頁與頁面管理安排內容位置；資料管理提供能持續更新的內容。

功能主要工作
品牌樣式與配色選整站模板與品牌顏色，統一標題、卡片、按鈕及區塊的設計語言。
首頁管理新增或選取模塊，設定可用版面、內容、排序與顯示。部分必要區塊位置固定。
頁面管理建立內頁，選頁型、版型、內容來源、導覽位置與連結。
內容資料管理維護文章、商品、FAQ、據點等資料，供首頁、列表與適用的詳情頁引用。
網站基本資訊管理 Logo、站名、聯絡方式等共用內容。頁首、頁尾與共用行動區的配置依實際後台確認。

模塊、頁型與版型的區分

首頁用模塊組成不同區段，內頁依用途選擇頁型；同一模塊或頁型可有不同版型。實際項目與畫面直接參閱下一節的來源清單。

04 / 設計與開發協作流程

既有能力優先，不足的部分提出新設計

同一個網站可以同時包含套版、視覺客製與功能擴充。每個新畫面先確認內容與操作，再進入轉碼。

新設計提交時，說明這五件事

  1. 出現在哪個頁面或區塊。
  2. 現有樣式或模塊為什麼不適合。
  3. 哪些欄位與元件沿用，哪些需要增加。
  4. 桌機、手機與互動狀態如何呈現。
  5. 哪些已確認，哪些仍需開發評估。
分兩次確認畫面：設計先檢查轉碼後的 HTML／CSS；開發完成平台整合後，再共同確認實際結果。Figma 正確不代表轉碼結果已正確，靜態預覽正確也不代表平台功能已完成。
05 / 設計轉碼的 UI 規則

先定義畫面怎麼顯示，再讓 AI 實作

本節聚焦設計端需要交代的內容。平台語法、資料庫、正式 API、驗證管線與程式轉換由開發處理。每案應先完成欄位與畫面確認，未定項目寫「待確認」。

元件辨識必填欄位顯示條件內容變化品牌樣式響應式互動狀態連結與入口素材

01　模塊、元件與欄位辨識

需要定義
區塊用途、版面名稱、重複項目，以及其中的文字、圖片、按鈕與互動元件。
設計／轉碼要求
Figma 與 HTML 使用一致的用途命名；保留可辨識的區塊結構。以交付對照表或簡單 HTML 註解標明用途，不自行發明平台專用標記。
完成確認
開發可以辨認整個區塊、每筆項目及各個欄位，不需猜測哪個元素要換成後台資料。
描述範例服務介紹／卡片版：一個區塊標題、可重複的服務項目；每項有圖片、名稱、說明與連結。三張卡片沿用相同結構。

02　必填、選填與內容來源

需要定義
每個欄位的名稱、用途、必填／選填、內容來源，以及未填時的處理。
設計／轉碼要求
依確認過的後台欄位製作，不因畫面需要自行新增資料。必填代表正式內容要求，不代表假資料可補成完成；示範值需標明。
完成確認
每個畫面元素都能對應欄位或固定裝飾；新增欄位與資料來源已另外標記。
示例欄位要求空值處理
服務名稱必填標記缺漏並請求補充，不自動生成正式文案。
服務說明選填不顯示說明，收掉對應間距。
圖片依本案確認使用核准的缺圖策略，不擅自找外部圖片。
連結文字／網址依是否開啟按鈕確認有文字但沒有網址時，標記待補；不使用假連結冒充完成。

上表為填寫方式範例，非所有模塊共用的必填規格。

03　欄位顯示與缺漏內容

需要定義
每個欄位在這種版面是必須顯示、條件顯示或不使用；有沒有圖片、按鈕或資料時，區塊如何變化。
設計／轉碼要求
空內容不留下標題、空框、按鈕或多餘留白。未使用欄位需註明，不默默省略；只影響顯示，不要求設計實作後台儲存邏輯。
完成確認
檢查完整資料、少一個選填欄位、沒有圖片與整段無資料等適用情況。
描述範例副標題留空時不顯示，主標題與卡片之間改用單一間距；兩顆按鈕都關閉時整列收起。整段 0 筆資料是否隱藏，需依本案確認。

04　文字長度、項目筆數與排版適應

需要定義
筆數的允許範圍與建議值、文字換行／截斷、卡片高度、最後一列對齊方式，以及是否需要分頁或更多入口。
設計／轉碼要求
不依賴剛好三張卡片或一行標題；不把內容轉成圖片；不以縮小字體或直接裁掉內容解決爆版。
完成確認
用本案允許的最少／最多筆數與長標題檢查；一般正文可讀，不與圖片或按鈕重疊。
描述範例服務卡片在本案確認的範圍內自然換行；標題可兩行以上，卡片隨內容增高。最後一列靠左；若需要等高，明確說明按鈕對齊方式。

05　品牌配色與共用樣式

需要定義
主色、輔色、背景、區塊底色、品牌文字、標題／正文及次要文字的角色；字級、圓角、陰影與間距共用規則。
設計／轉碼要求
附色彩角色對照，CSS 將共用顏色集中管理。開發提供實際變數名稱後再沿用；名稱尚未確認時標記對照需求，不自行宣稱符合平台。品牌 Logo、照片原色與第三方品牌色等例外需列出。
完成確認
主要元件風格一致，換色時文字仍可讀。新增整站風格與單一模塊新排版需區分。
描述範例主要按鈕用主色、一般卡片用區塊底色、正文用閱讀文字色。LINE 的識別色若需保留，列為明確例外。

06　桌機、手機與中間寬度

RWD 確認尺寸畫面寬度確認重點
桌機1440px整體排版、內容最大寬度、圖片與留白。
平板768px減欄、圖文順序、導覽與按鈕是否合適。
手機380px閱讀、圖片裁切、操作空間與橫向溢出。

單位為 CSS px，指畫面／瀏覽器視窗寬度，高度依內容延伸。三種尺寸皆需有可確認的畫面或預覽；未提供 Figma 稿的尺寸依約定規則實作後由設計確認。尺寸之間仍須檢查連續變化；以上不是固定 CSS 斷點。

需要定義
容器寬度、左右留白、欄數、閱讀順序、字級、圖片比例與裁切、導覽及按鈕排列。斷點採用平台確認值；未定時由開發試排後確認。
設計／轉碼要求
新排版先選下列一種確認方式；中間寬度自然伸縮可用文字規則，獨立結構或操作變化需補畫面／預覽。
完成確認
除了指定尺寸，也檢查連續縮放時的換欄、裁切、橫向溢出與操作；表格若需橫向捲動，限制在表格區域內。

先確認桌機與手機稿

設計提供桌機＋手機畫面及規則。轉碼後檢查中間寬度與互動。

以手機預覽完成確認

設計提供桌機稿＋規則，AI／開發先做手機預覽，再由設計確認修正。需事先安排審查與工時。

描述範例卡片由三欄減為兩欄，再減為一欄；順序不變。圖片維持指定比例，標題自然換行，手機按鈕滿寬。人物裁切、選單展開等需明確確認。

07　互動宣告與畫面狀態

需要定義
元件用途、觸發方式、開啟／關閉狀態、鍵盤焦點及手機替代操作。例如 FAQ 展開、分類切換、輪播或表單。
設計／轉碼要求
先對照開發提供的可用互動清單；未支援的互動列為提案。正式表單、搜尋與功能程式由平台處理；設計交代外觀、位置及狀態，交付註記清楚。
完成確認
重要內容不只靠滑鼠移入顯示。若需 JS 展示狀態，先確認是否允許獨立 demo；未約定時提供狀態稿與說明，不夾帶正式功能。
描述範例FAQ：點擊問題切換答案顯示；圖示需呈現開啟／收合差異。是否允許同時開啟多題依本案確認。聯絡表單另提供空白、錯誤與完成提示的視覺參考，實際送出由開發接入。

08　按鈕、連結與內容去向

需要定義
按鈕文字、是否顯示、站內／外部／頁內連結、是否另開，以及目標頁是否存在。
設計／轉碼要求
先確認每類資料是否有詳情頁；沒有時不設計「看詳細」入口。尚未提供的目標標記待補，不能用「#」或猜測網址當成有效連結。
完成確認
每個可點項目有去向清單；不可操作與停用狀態有明確表現，不靠點擊後才發現缺少功能。
描述範例據點卡若只有外部地圖連結，就提供「導航」；不自行增加據點詳情頁。內頁是否支援由開發確認。

09　圖片、圖示與素材

需要定義
素材名稱、用途、比例、主體位置、手機替代圖、透明底需求、圖示選擇與授權來源。
設計／轉碼要求
交完整設計圖，也交獨立素材與可複製文案。素材格式、大小與圖示清單依開發提供的可用規格；區分設計原稿、展示素材與客戶可上傳格式。
完成確認
圖片不拉伸、主體不誤裁，缺圖策略一致；沒有未說明的外部素材、第三方嵌入或字型依賴。
描述範例商品照片完整保留產品輪廓；情境圖可裁切但保留人物。若同一張圖無法適應手機，另交手機素材。圖示不得只靠固定裝飾字形代替而未註明。
開發先提供的 UI 參考：本案可用欄位與必填、筆數上下限、互動清單、色彩角色與變數對照、斷點、詳情頁能力、素材與圖示限制。尚未確認的數值或能力不得直接沿用舊文件當成定案。
06 / 給 AI 的轉碼提示詞

讓 AI 依已確認的 UI 規則製作

先附 Figma 連結與權限，或桌機／手機設計圖、獨立素材及文案，再貼上共用提示詞，補上本次模塊規則。Figma、Dev Mode 或 MCP 是取得設計資訊的方式，不限定一定使用其中一種。

使用前：把中括號內容換成本案資訊，刪除不適用項目。沒有資料就標「待確認」，不要讓 AI 補成看似已完成的規格。

提示詞一：共用轉碼要求

請依附件的 Figma／設計圖與素材，製作可供瀏覽器預覽的 HTML 與 CSS。

【本次範圍】
客戶／網站：[名稱]
頁面與區塊：[使用位置、模塊／頁型、版面名稱]
設計來源：[Figma 連結，或設計圖檔]
確認方式：[桌機＋手機稿／桌機稿＋手機預覽確認]
素材與文案：[檔案清單]
已確認的 UI 規則：[貼上欄位、顯示、響應式及互動要求]

【製作要求】
1. 忠實依設計呈現，不擅自改風格、增加區塊或刪除資訊。
2. 區塊、元件與重複項目保持清楚結構；文字保留為文字，圖片、按鈕及清單分開，不把整段做成圖片。
3. 依提供的欄位對照製作。必填缺漏請列出，不自行補正式內容；選填空值、缺圖、無按鈕與空資料依規則處理，不留下空框或多餘間距。
4. 測試確認過的最少／最多筆數與長文字，不只製作示範圖中剛好的資料量。
